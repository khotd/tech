##Выводы
1. **Пропускная способность:** Redis показывает более высокую пропускную способность на малых и средних нагрузках за счёт in-memory архитектуры и отсутствия ACK-протокола.
2. **Влияние размера сообщения:** RabbitMQ стабильнее переносит увеличение payload (>10KB) благодаря потоковой обработке и механизму back-pressure. Redis начинает терять эффективность при росте payload из-за overhead на сериализацию и сетевого буфера.
3. **Точка деградации (Single Instance):**
   - Redis: деградация начинается при `~5000-8000 msg/sec` с payload >1KB.
   - RabbitMQ: сохраняет стабильность до `~10000 msg/sec`, деградация проявляется при превышении лимитов RAM/Disk.
4. **Рекомендация:** Для low-latency систем с мелкими сообщениями — `Redis`. Для enterprise-очередей с гарантиями доставки и сложной маршрутизацией — `RabbitMQ`.
